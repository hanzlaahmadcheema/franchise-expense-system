# Jazz Load — CSV export

Generated by `../extract_jazz_csv.py` from `Jazz Load August-2026 FIXED.xlsx`
(read-only). Re-run with `python3 ../extract_jazz_csv.py`; output is
byte-identical each time. Pass `--no-check` to skip reconciliation, or `-o DIR`
to write elsewhere.

| file | rows | grain |
|---|---|---|
| `summary_balances.csv` | 31 | one per day, the SUMMARY date table |
| `summary_commissions.csv` | 4 | the month commission block |
| `daily_overview.csv` | 31 | per-day balances, day totals, commission |
| `daily_distributors.csv` | 430 | one per distributor per day |

## Conventions

- **Numbers are 3dp**, matching what the sheet displays. A cell that is blank in
  the sheet stays blank in the CSV, so a blank is never confused with a real `0`.
- **Dates are ISO** (`2026-07-01`).
- **Names are right-stripped.** Three names carried trailing spaces in the
  sheet (`ADNAN `, `ANNI `, `HUSSAIN `).
- **Commission labels are the cell's own text**, not re-derived from the rate, so
  `summary_commissions.csv` reflects what the workbook actually says.

## Deliberately excluded

- **`N18`/`O18`/`P18`** on each day sheet. A self-contained chain
  (`N18 = K18*2.4/100`, `O18 = K18-N18`, `P18 = J18-O18`) that used to feed
  `M25`. `M25` now reads `J18` directly, and no cell outside this trio
  references it, so all three are dead. Day 23's `P18` is still a hardcoded
  `2970`; it is preserved verbatim and affects nothing.
- **`L23`** on each day sheet. It is `=J23`, an exact duplicate of the in-hand
  balance. Including it invites double-counting.
- **4 placeholder rows** on day 2 (S.No 10–13) have neither a name nor a DO line
  and were skipped; they carry only zeros. The script reports this on every run.

## Notes on the data

- **S.No 14 is spelled two ways across the month.** It reads `OTHER` on day 1
  and `OFFICE` on days 2–31. Almost certainly one entity, which is why the
  month shows 16 distinct names for 15 real ones. Left as-is.
- **DO line `3027107343` is reused on all 31 days** — by `FIXED LINE` (always
  S.No 10, which carries the money) and by S.No 14, which is `0.00` on every
  single day. So no cash is double-counted; the cost is that **`do_line` is not
  a unique key** here. Group or join on `(day, s_no)`, not on `do_line`.
- The commission block lives in `SUMMARY` rows 2–6, which are also day 1–5's data
  rows. `summary_commissions.csv` separates it out.
- `Month Total Upfront Commissions` is blank. That cell sits inside the merged
  range `J2:L3`, so it cannot hold a value. It is kept as a row with an empty
  value rather than dropped, so the gap is visible.

## Verification

The script reconciles before writing and exits non-zero on any failure:

- each day's `TOTAL` row equals the sum of its distributor rows
- every day `M27 = M25 + M26`
- `SUMMARY` balances match the 31 day sheets (186 comparisons)
- `SUMMARY` `F = C+D+E` and `H = F-G` on all 31 rows
- opening balance chains across all 31 days
- month commission totals match the sum of the days
- the exported rows are re-verified against the sheet, so a mistyped cell
  reference cannot pass by reading the sheet twice
